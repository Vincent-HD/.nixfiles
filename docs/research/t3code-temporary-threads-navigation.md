## Existing frontend seams

- **Create and promote through the normal thread UI.** `useNewThreadHandler` creates a client-side draft and navigates to `/draft/$draftId`; the server thread is only promoted later. `ThreadRouteView` deliberately keeps one `ChatView` mounted across draft-to-server promotion. A temporary marker must start on the draft and survive promotion into the durable thread; a server-only marker misses unsent drafts and a local-only marker disappears from other clients. [New draft flow](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/hooks/useHandleNewThread.ts#L324-L381), [promotion view](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/ThreadRouteView.tsx#L27-L31), [draft/server rendering](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/ThreadRouteView.tsx#L159-L187).
- Draft composer state is persisted locally, and `discardComposerDraft` is an undoable action. Confirmed temporary-draft exit therefore needs an explicit draft cleanup path too; deleting a server thread does not clear an unpromoted draft. [Persisted draft state](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/composerDraftStore.ts#L130-L145), [draft discard](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/lib/discardComposerDraft.ts#L14-L30), [clear draft session](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/composerDraftStore.ts#L2791-L2806).
- **There is no temporary-conversation control in the inspected frontend.** The thread action menu handles rename, archive, delete, and other existing actions; the create handler has no temporary option. The app can render either the current or legacy sidebar, so a “Mark temporary” item added there needs parity or a shared action. [Thread action menu](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/hooks/useThreadActionMenu.ts#L179-L245), [delete action](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/hooks/useThreadActionMenu.ts#L290-L314), [sidebar variants](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/AppSidebarLayout.tsx#L424-L433).
- **SPA navigation is the reliable place to ask.** Sidebar selection calls `router.navigate`; the app's back/forward shortcuts call `window.history.back/forward`. I found no route blocker in the inspected routes; root `beforeLoad` handles authentication and redirects. A shared route-level blocker should cover sidebar/search/keyboard selection, new-thread navigation, links, and in-app back/forward. [Sidebar navigation](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/Sidebar.tsx#L1165-L1177), [history shortcuts](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/AppSidebarLayout.tsx#L223-L257), [root route](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/routes/__root.tsx#L90-L120).
- **Reuse the themed confirm host and thread deletion path.** `requestConfirmDialog` returns an async boolean and `ConfirmDialogHost` is mounted for the authenticated app. The shared dialog currently has fixed “Cancel” / “Confirm” labels and only a `variant` option; a three-way “Keep / Stay / Discard” dialog needs a custom host or API extension. Existing delete confirmations are gated by `confirmThreadDelete` (default true but user-configurable), so temporary-exit confirmation must be mandatory independently. [Confirm request](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/confirmDialog.ts#L72-L97), [dialog buttons](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/ConfirmDialogHost.tsx#L68-L94), [options](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/packages/contracts/src/ipc.ts#L1223-L1233), [delete setting](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/packages/contracts/src/settings.ts#L377-L382).
- **Use the existing delete wrapper, with navigation coordination.** It calls `stopThreadSession` for a thread with a runtime, dispatches the existing `thread.delete` command, clears draft/terminal/preview state, and navigates to a fallback if the deleted thread is currently routed. A navigation blocker that also resumes the user's intended destination must prevent this internal fallback from replacing that target or causing a second prompt. The wrapper can also ask whether to remove an orphaned worktree (or follow automatic worktree-cleanup settings); decide whether temporary means conversation-only before wiring it in. Call the deletion operation after the temporary-specific confirmation, not `confirmAndDeleteThread`, which can add a second setting-dependent delete prompt. [Delete wrapper and side effects](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/hooks/useThreadActions.ts#L398-L535), [thread delete command](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/packages/client-runtime/src/operations/commands.ts#L409-L428), [optional worktree prompt](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/hooks/useThreadActions.ts#L438-L483).

## Recommended exit contract

For a minimal first version, define **leave** as a route change away from the temporary conversation, including selecting another sidebar thread, starting another draft, opening another app route, or in-app back/forward. Show “Leave this temporary conversation?” with “You will lose this conversation.” Offer **Stay** and **Leave and discard**. On discard, complete the existing delete/cleanup path while the renderer is alive, then continue to the user's requested destination. A separate “Keep permanently” action in the thread menu avoids expanding the shared confirm API to three choices. The in-app close of a right-panel surface, preview/browser tab, or terminal is not leaving the conversation and should not delete it: `closedViewStore` records only panel tabs and preview browsers, and preview-tab close is a separate operation. [Closed-view types](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/closedViewStore.ts#L16-L22), [preview-tab close](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/preview/closePreviewSession.ts#L22-L39).

The normal `ChatView` route is singular; panels are attached to the current thread. Desktop requests a single application instance and tracks one main chat window. The web app can still be open in multiple browser tabs/windows or clients: a confirmed delete is thread-wide, so another view of that thread becomes missing and, when its environment has other threads, redirects to `/`. No cross-window “another view is open” lease was found. Minimal semantics should state that discard removes the shared thread everywhere; preventing deletion while another client views it would require view leases/co-ordination. [Single chat route](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/routes/_chat.tsx#L198-L209), [desktop single-instance lock](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/app/DesktopClerk.ts#L108-L122), [main-window reuse](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/window/DesktopWindow.ts#L854-L870), [deleted route becomes missing](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/threadRoutes.ts#L32-L55), [missing-route redirect](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/components/ThreadRouteView.tsx#L146-L157).

## Unload and desktop boundaries

| Exit | Current behavior and feasible handling |
| --- | --- |
| In-app route or SPA back/forward | Can await T3's custom dialog and delete command before route transition. |
| Web refresh, tab/window close, or browser back that leaves the document | Current `beforeunload` listeners only flush persisted composer/UI state. A browser-native prompt can warn, but browsers control its generic text and do not provide a reliable async post-confirm callback for deletion. Do not promise cleanup here from frontend unload code. To guarantee cleanup on every such exit, the backend needs an expiry/lease cleanup path; otherwise document route departure as the guaranteed scope and treat the native warning as best effort. [Composer flush](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/composerDraftStore.ts#L142-L146), [UI flush](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/uiStateStore.ts#L458-L462). |
| Desktop main-window close / app quit | `BrowserWindow` close currently only flushes bounds. On macOS, closing the last window leaves the app running; other platforms quit after all windows close. The configurable Cmd/Ctrl+Q direct/hold/double-press behavior is a quit-shortcut guard, not a temporary-thread prompt. Desktop has an `ElectronDialog.showMessageBox` service, but using the existing React dialog on close requires preventing close and an IPC handshake that keeps the renderer alive through confirmation and deletion. Test both window-close and app-quit paths separately. [Window close handler](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/window/DesktopWindow.ts#L692-L694), [quit shortcut integration](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/window/DesktopWindow.ts#L641-L663), [platform quit behavior](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/app/DesktopLifecycle.ts#L244-L254), [quit shortcut behavior](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/window/QuitHold.ts#L137-L198), [native dialog service](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/desktop/src/electron/ElectronDialog.ts#L98-L102). |

## Active work, scope, and tests

Desktop mounts `RunningThreadKeepAlive`, and the thread state tracks preparing/queued/starting/running work after navigation. Discard through the current frontend wrapper stops a non-null runtime before deletion. The client also derives live and settled subagent counts, but the existing delete prompt does not describe active work or child agents. Coordinate the exact stop/cascade consequence with the separate backend investigation before promising it in UI copy. [Keep-alive mount](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/routes/__root.tsx#L233-L236), [running state and keep-alive](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/apps/web/src/state/threads.ts#L53-L115), [subagent counts](https://github.com/pingdotgg/t3code/blob/044f07257c9684ae4543bd1e1ebf9c394e9e3830/packages/client-runtime/src/state/threadSubagents.ts#L30-L70).

**Effort:** draft/thread marker propagation plus a route blocker and deletion-destination coordination is a focused medium frontend change. Desktop close/quit adds a main-to-renderer handshake. Reliable browser-unload cleanup is cross-tier work, not a frontend-only change. Suggested focused tests: draft-to-server promotion and permanent toggle; route blocker across sidebar/new-thread/settings/search/history with Stay and discard; delete failure and original-destination preservation; panel/preview close does not discard; worktree confirmation behavior; active run and active subagent warning/stop behavior; desktop close versus quit on macOS and other platforms; two browser windows viewing the same thread; native browser unload warning without claiming a guaranteed async delete.
