starship + starship-jj

Starship Starship GitHub starship-jj

Starship is the fast cross-shell prompt. The custom JJ segment calls starship-jj only inside Jujutsu workspaces to show bookmarks, current change text, state, and metrics.

Prompt checks

starship explain
starship module directory
jj root --ignore-working-copy
starship-jj --ignore-working-copy starship prompt

JJ signal shown

  • Bookmarks near the current commit.
  • Commit text and conflict/divergent/hidden state.
  • Changed files, insertions, and deletions.

Prompt + JJ

Starship is enabled for Bash and Zsh, with a custom JJ segment that appears only inside Jujutsu workspaces.

What the prompt knows

The custom module runs starship-jj --ignore-working-copy starship prompt when jj root --ignore-working-copy succeeds. Snapshotting on every prompt can hang in large colocated repos; skipping it keeps the shell responsive.

Starship website starship-jj GitLab
  • Change contextcurrent change, bookmark, and commit message
  • Stateconflict, divergent, empty, immutable, or hidden status
  • Metricschanged files plus added and removed lines
jj-aware prompt
~/src/app branch feature/login "tighten cli setup" [3 +42-9] $ jj status Working copy changes are reflected before the command runs.

Compatibility

The module is shared, but a couple of platform details stay explicit so each machine gets the right owner.

Linux: pc-fixe

Ghostty is installed from nixpkgs as part of the shared module. The same Zsh, Starship, Zoxide, Inshellisense, FZF, Yazi, Delta, and modern CLI packages are enabled through Home Manager.

macOS: macbook-pro

Ghostty remains externally or Homebrew-owned until the live macOS inventory assigns its final owner, while the command-line tools are Nix-owned. JetBrains Toolbox scripts, Bun, and OrbStack shell integration are preserved for Darwin.

Managed by config.flake.modules.homeManager.commandLine. No JavaScript, no build step, just a local HTML map of the terminal setup.
